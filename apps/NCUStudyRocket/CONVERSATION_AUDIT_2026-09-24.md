## 本次故障的完整原因

这次并非单一“命名空间没注册”，而是四层问题叠加：

1. 固定学业任务保存了 `studyrocket` 动态工具声明，但工具调用的实际处理器属于发起回合的 StudyRocket app-server 连接。从应用打开 Codex 历史页后直接续聊，任务仍能看到工具名称，当前连接却没有 StudyRocket 处理器，因此返回 `Unsupported dynamic tool namespace: studyrocket`。
2. Desktop、Host 和 Codex 页面可能争用同一固定任务。原任务被 Codex Desktop 占有时，Host 会遇到 `already has an active writer`；已恢复的任务被卸载后，首个 `turn/start` 还可能返回精确的 `thread not found`。
3. Host 的 health、自检和历史读取只证明本地协议与任务读取可用，不证明远端模型、当前 writer、工具处理器和 proposal store 的端到端链路。此前把 `dynamicToolsReady=true` 当成“草案已修复”，证据不足。
4. 维护 Skill 当时禁止任何 `exec` 包装，但当前 Codex 版本会把动态工具正式暴露为 `functions.exec` 内的 `tools.studyrocket__propose_changes`。按调用外形拒绝正式声明，使已经恢复的链路又被错误阻断一次。

限流 `429 Too Many Requests` 是之后一次重试遇到的独立远端故障。它延迟了提交，但不是命名空间问题的根因。

## 对近期对话的主要发现

### 1. 验收标准经常停得太早

多个维护对话把 Swift 构建、签名、Host health、`202 Accepted` 或工具目录可见当成完成证据。这些检查各自有价值，但不能替代真实回合终态、草案队列、文件写入或真机画面。2026-09-21 的首次路由修复已经明确“真实草案验收仍未完成”，后续仍过早使用“已修复并发布”的表达。

改进：按“请求进入 -> 回合完成 -> 工具成功 -> proposal store -> 用户确认 -> 文件验证”逐级报告，不跨级推断。

### 2. 长会话积累了过多隐含状态

“修复今日安排多项目显示”包含大量工具调用、多次上下文压缩和中断，横跨 Shared、Host、Desktop、Mobile、Widget、部署和 Git 发布。长链条中容易把某次构建结果误用于后续源码，也容易遗漏真实设备和运行中 Host 仍是旧版本。

改进：每次可验证里程碑后立即把稳定结论写入项目知识库；新的轮次重新核对 HEAD、安装包、运行进程和真实文件哈希。压缩摘要只负责续接，不负责验收。

### 3. 同一状态在不同层被混为一谈

近期对话曾把 HTTP 可达、SSE 状态、模型认证、动态工具、计划写入和 Mobile 队列同步视为一个“连接正常”。历史上因此出现 health 全绿但模型 401、SSE 重连但写入冲突、手机能发送却没有回答、Host 更新而手机仍显示旧 snapshot 等现象。

改进：分别记录 Host HTTP、SSE、模型回合、工具调用、proposal、Markdown revision、Mobile generation 和设备安装版本；业务 409/422 不污染全局连接状态。

### 4. 对话入口的产品文案具有误导性

“在 Codex 中打开”让用户合理地认为可以在那里继续同一学业对话并提交计划。实际上该页面只能可靠查看历史，继续发送会绕过 StudyRocket 工具处理器。

改进：Desktop 已改为“在 Codex 查看历史；修改计划请在此处发送”，帮助页也明确该边界。长期方案应让任务所有权和工具处理器成为产品协议，而不是依靠用户记住入口差异。

### 5. 错误恢复缺少幂等边界

过去遇到失败时倾向于重启、升级协议或重试整个请求。若失败发生在 `turn/start` 之后，盲目重发可能重复用户消息或草案。

改进：只对精确且发生在回合创建前的 `thread not found` 恢复并重试一次；active writer 通过保留旧任务、迁移有限历史并新建固定任务解决；401、429、超时各自处理。结果不明先查历史、SSE 和 proposal store。

### 6. 事实与隐私输出仍需更严格

部分学业对话把高中经历写成对外简介时使用了精确奖项或专利表述，而仓库档案已注明若干名称、级别和届次需按证书复核。另有一个邮件登录链接被直接保存在任务标题中，可能包含短期会话参数。

改进：对外材料继续区分“用户提供”“仓库官方文件”“待核实”，证书未复核时不升级措辞；会话审计、标题和日志摘录一律去除登录 URL 查询串、凭据、设备标识和个人联系方式。

### 7. 中断或仅计划的对话不能当作完成

近期记录中存在只有用户消息、被中断、只生成方案或只形成草案的对话。标题、摘要和 `task_complete` 事件不能证明文件、应用或设备状态已经改变。

改进：项目知识库只吸收稳定产品决策、当前源码事实、带验证的实现和明确失败模式；其余标为“仅计划”“被中断”或“待用户确认”。

## 已落实的改进

- 修复协议恢复后聊天仍停在 unavailable 的状态机问题。
- 当旧任务被 Desktop 占有时，保留旧任务并迁移有限文字上下文到新的固定学业任务。
- 对精确 `thread not found` 只做一次回合前恢复重试。
- Desktop 入口和帮助文案明确 Codex 页面用于查看历史。
- 维护 Skill 改为按正式工具声明判断，不再错误禁止 `functions.exec` 中的动态工具入口。
- 维护 Skill 新增全量会话审计方法、错误分类、重试边界和端到端草案验收门槛。
